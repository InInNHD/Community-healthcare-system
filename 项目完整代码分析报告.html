项目概览

这是一个在 Guns Admin / Roses Kernel 基础上二次开发的单体社区医疗管理系统。后端采用经典 Controller → Service → Mapper → MySQL 分层，页面由 Beetl 输出骨架，再由 jQuery 和 Bootstrap Table 调用 JSON 接口完成数据交互。三个角色门户共享同一数据库，但按登录角色和用户—业务档案绑定关系呈现不同视图。

业务模块

下列模块说明来自控制器、服务、实体、SQL 和前端请求的交叉核对。

Shiro + Session + RBAC + JWT

身份认证与权限

ShiroConfig 配置过滤器链和 RememberMe；ShiroDbRealm 从用户、角色、菜单加载认证授权信息；PermissionAop 处理自定义 @Permission；/gunsApi 使用 Bearer JWT。

Spring MVC + MyBatis-Plus + AJAX

管理员门户

聚合患者、医生、预约、药品、健康档案与公卫统计；支持医生/患者业务档案批量同步为登录账号，并提供预约和慢病看板。

Beetl + REST 风格 JSON + MyBatis-Plus

医生门户

围绕当前登录医生查询预约队列、患者档案、病历、药品、慢病随访及公共卫生记录；实现开始/结束问诊和医生工作台统计。

Beetl + jQuery/AJAX

患者门户

将登录账号关联到 patient_info，展示个人健康档案、预约、病历、药品、慢病、接种及老年体检；提供预约新增、修改、取消、完成。

Spring Service + MyBatis-Plus

慢病管理

管理高血压、糖尿病、冠心病、脑卒中、慢阻肺、慢性肾病档案；按疾病计算风险等级，维护随访和计划，并生成疾病专属随访模板及到期提醒。

Spring MVC + MyBatis-Plus ActiveRecord

公共卫生

覆盖预防接种、孕产妇/产后访视、儿童体检、老年体检、传染病报告与审核；以软删除、状态筛选和统计接口支撑页面。

事务服务 + 批次库存

药品与库存

药品资料支持分类、图片、软删除和恢复；库存服务在同一事务内更新总库存、出入库流水和批次余量，提供低库存预警和合并流水。

CRUD + Apache POI

患者档案与病历

患者基本信息、健康指标和就诊病历分层存储；病历支持单条/按患者与日期区间导出 Excel，并提供打印视图。

Guns / Roses 内核

系统管理

用户、角色、菜单、部门、字典、通知、登录日志和业务日志组成后台基础能力；AOP 自动记录业务变更，包装器把外键/状态转换成人类可读文本。

安全、质量与可维护性

以下是静态审阅发现，未对源代码进行修改。优先级按被利用可能性、影响范围与升级成本综合判断。

级别问题依据与建议
高依赖版本整体过旧Spring Boot 2.0.1、Shiro 1.4、JJWT 0.9、Beetl 2.9.3 均属于旧代版本，安全修复与 JDK 兼容性风险高。建议先建立回归测试，再分阶段升级到受支持版本。
高密码哈希强度不足且存在固定初始密码ShiroKit 使用 MD5 + 1024 次迭代；账号同步直接设置 111111，DataInitConfig 还会把指定账号重置到默认密码。应改用 Argon2id/bcrypt/scrypt，并强制首次登录改密。
高JWT 密钥完全依赖环境变量JwtConstants.SECRET 来自 JWT_SECRET；缺失时可能导致启动后鉴权异常，且无密钥轮换/issuer/audience 校验。应在启动期校验强随机密钥并加入签发方、受众和轮换策略。
中动态排序 SQL 使用 ${orderByField}登录日志和操作日志 Mapper 使用字符串替换拼接 ORDER BY。虽然通常来自表格字段，仍应在服务端做字段白名单映射，避免 SQL 注入。
中Controller 承担过多业务逻辑三个门户控制器长达数百行，直接拼装查询、实体和状态流转，造成事务边界、复用与测试困难。建议拆出应用服务/查询服务和 DTO。
中关联关系仍混用姓名与 ID迁移脚本已引入 doctor_id，但部分查询和展示仍依赖 doctor_name/patient_name；姓名变更会产生历史一致性问题。应以 ID 为主键关联，姓名只作快照。
中拼写错误已固化到领域模型patient 被写成 paient，模块目录还有 pateint_health_manager。数据库列、Java 字段、JSON 与前端同时依赖该拼写，重构需兼容映射和迁移。
中软删除策略不完全统一部分实体通过 is_deleted 过滤，部分仍物理删除或未在所有查询中显式过滤。建议统一逻辑删除插件、全局查询条件和恢复审计。
低N+1 查询与内存聚合门户列表逐条加载用户或药品名称，库存流水先各取 50 条再内存合并；数据量增大后会拖慢。可用联表/批量 IN 查询与数据库分页。
低测试覆盖偏基础设施现有测试集中在系统 Mapper 和示例多数据源，医疗业务、权限隔离、库存事务、风险分级和导出缺少自动化验证。
