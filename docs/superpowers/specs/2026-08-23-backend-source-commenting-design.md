# 后端源码高可读性注释设计

## 目标

为 `backend/src/main` 中的生产 Java 源码、Spring Boot 配置和 Flyway 数据库迁移补充统一、准确且可长期维护的简体中文注释，使维护者无需反复追踪调用链即可理解模块职责、业务规则、安全边界、事务副作用和数据约束。

本次工作只增加或优化注释，不改变程序行为、方法签名、注解、配置值、SQL 执行顺序或数据库结构。

## 范围

### 纳入范围

- `backend/src/main/java/com/community/healthcare` 下的启动类与全部业务模块。
- `backend/src/main/resources/application.yml`。
- `backend/src/main/resources/db/migration` 下 V1–V11 Flyway 迁移脚本。
- 为业务包新增的 `package-info.java`。

### 排除范围

- `backend/src/test` 测试代码。
- `frontend` 前端代码。
- `legacy` 历史系统代码。
- `target`、`dist`、`node_modules` 等构建产物或依赖。
- OpenAPI 等自动生成代码。

## 语言与术语

- 注释统一使用简体中文。
- JWT、MFA、CSRF、DTO、JPA、Flyway、幂等键等通用技术术语保留英文。
- 业务状态、角色名和字段名在需要对应代码或数据库时保留原始标识符，并在中文上下文中解释含义。
- 不在注释中记录密码、密钥、令牌或其他敏感值。

## 注释层级

### 模块级说明

每个承担独立业务职责的包增加 `package-info.java`，至少说明：

- 模块解决的业务问题。
- 模块拥有的数据或规则边界。
- 与其他模块交互的主要方向。
- 不属于本模块职责的事项。

### 类型级说明

Controller、Application Service、领域对象、Repository/Store、Adapter、配置类和安全类增加中文 Javadoc。类型注释回答：

- 该类型负责什么。
- 由谁调用或在什么流程中使用。
- 依赖哪些外部能力或相邻模块。
- 关键的不变量、权限边界或生命周期约束是什么。

简单枚举和纯数据载体只解释业务语义、合法值、单位或兼容性要求，不机械描述 Java 语法。

### 方法级说明

公共方法以及具有明确业务含义的包级方法增加 Javadoc。根据实际需要说明：

- 业务目的与前置条件。
- 参数和返回值的业务语义。
- 状态变化、持久化、审计或外部调用等副作用。
- 可能抛出的业务异常。
- 权限、数据归属、幂等、并发或事务约束。

显而易见的 getter、构造器、简单转换函数和框架要求的样板方法不添加低价值注释。

### 行内说明

只在代码本身无法充分表达意图时添加 `//` 注释，重点覆盖：

- 状态机转换及拒绝非法转换的原因。
- 居民、医生和站点之间的数据隔离规则。
- 库存扣减、防止超卖和批次选择规则。
- 幂等、防重、并发冲突及重试处理。
- JWT 轮换、CSRF、MFA、首次改密和 Demo 账号之间的安全关系。
- 时间边界、风险分层和公共卫生规则中的业务依据。
- 为兼容旧字段、历史数据或外部接口而保留的特殊处理。

## 各代码区域的关注重点

| 区域 | 注释重点 |
|---|---|
| `clinical`、`encounter` | 接诊、病历签署、医嘱与居民门户数据边界 |
| `scheduling` | 时段占用、预约状态机、时间策略和幂等创建 |
| `residentregistry` | 居民主索引、证件保护、监护关系和人员访问策略 |
| `security` | 浏览器会话、CSRF、JWT 轮换、MFA、密码生命周期和 Demo 账号 |
| `identityorg`、`portal` | 中心/服务站层级、角色权限和门户开放策略 |
| `pharmacy`、`inventory` | 处方流转、批次选择、库存原子性和负库存保护 |
| `billing`、`insurance` | 账单状态、支付退款和医保模拟边界 |
| `familydoctor`、`publichealth` | 签约、服务任务、重点人群和规则评估 |
| `referral`、`integration` | 转诊状态、适配器契约、幂等重试和对账回执 |
| `audit`、`notification`、`quality` | 审计留痕、居民触达和质量指标用途 |
| `shared`、`config` | 跨模块基础契约和环境初始化边界 |

## 配置与数据库迁移

### `application.yml`

使用 `#` 按配置域说明：

- 配置项服务的运行场景。
- 环境变量覆盖方式。
- Demo 与正式模式的差异。
- 正式环境必须满足的安全约束。
- 单位、默认值和启用条件等非显然信息。

不重复解释 Spring Boot 已有的标准配置名称。

### Flyway SQL

每个迁移脚本使用 `--` 增加文件头和业务分段说明。文件头说明迁移目标、前置版本假设和不可逆影响；分段注释说明表、索引、外键、唯一约束、兼容字段和初始化数据的业务目的。

不逐行翻译 DDL/DML，不改变迁移版本、语句次序、分隔符或任何 SQL 内容。

## 禁止事项

- 不添加“获取用户名”“遍历列表”“返回结果”等复述代码的注释。
- 不添加作者、日期和手工维护的修改记录。
- 不添加无明确行动方案的 TODO 或“以后优化”。
- 不通过注释掩盖命名不清、职责混乱或潜在缺陷；发现问题只记录在实施结果中，不借本任务修改行为。
- 不声称代码具备其实际没有的事务、安全或一致性保证。

## 实施顺序

1. 基础层：`shared`、`audit`、Spring Boot 启动入口和模块级 `package-info.java`。
2. 核心医疗：`clinical`、`scheduling`、`encounter`、`residentregistry`。
3. 安全与组织：`security`、`identityorg`、`portal`、`config`。
4. 业务扩展：`pharmacy`、`inventory`、`billing`、`insurance`、`familydoctor`、`publichealth`、`referral`、`integration`、`notification`、`quality`。
5. 资源文件：`application.yml` 和 V1–V11 Flyway 迁移脚本。
6. 全仓复核：删除重复、过时或语法翻译式注释，统一术语和表达。

## 验证与验收

每个实施批次完成后执行 Java 编译。所有批次完成后：

1. 运行完整后端测试。
2. 执行后端打包。
3. 检查版本差异，确认现有文件只修改注释，新增文件仅为 `package-info.java`。
4. 检查每个业务模块均有模块说明。
5. 检查每个承担业务职责的顶层 Java 类型均可从类注释理解用途。
6. 抽查复杂业务规则、安全边界、事务和状态转换，确认注释解释原因而非复述实现。
7. 检查配置和迁移脚本可在脱离源码调用上下文时独立理解。

最终必须保持 Maven 测试与打包通过，运行行为与注释改造前一致。
